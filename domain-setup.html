Domain connection checklist

Host: GitHub Pages for smakonin/CarbonKit, serving main at the repository root. Target custom domain: carbonkit.org. This checklist records intended DNS changes, not confirmation that they have been applied.

Public DNS observed on 1 November 2026: carbonkit.org A records 3.33.251.168 and 15.197.225.128; www CNAME carbonkit.org; nameservers ns41.domaincontrol.com and ns42.domaincontrol.com. No authenticated GoDaddy editing capability was available when this checklist was prepared.

In GoDaddy, open the domain portfolio, select carbonkit.org, and open DNS. Save the current zone records before changing them. Configure the GitHub custom domain before switching DNS. GitHub recommends domain verification first; use the TXT value generated by the account's Pages settings rather than inventing one.

Replace the two old apex A values with the four GitHub Pages values above; replace the current www target with smakonin.github.io. Keep unrelated MX, TXT and other service records. Check for conflicting AAAA/forwarding records; change only conflicts with this website target. Leave nameservers in place. Use GoDaddy's default TTL or 1 hour where offered.

After public DNS resolves to GitHub, check repository Settings > Pages for successful DNS and certificate provisioning, then enable Enforce HTTPS when available. Check https://carbonkit.org and https://www.carbonkit.org, the canonical redirect, the document download and a nested page. GitHub notes DNS changes may take up to 24 hours.

Rollback, if needed: restore the saved prior A and www values and review GitHub custom-domain settings. A CNAME file or a GitHub setting alone does not change GoDaddy DNS. Domain completion requires successful DNS and HTTPS checks.

Official sources: GitHub Pages custom-domain management; GoDaddy Help, edit an A record and edit a CNAME record. The web appendix links these instructions. DNS values were verified against GitHub documentation on 1 November 2026.
